# M4.5 — media convergence

> Ready to execute the moment PR #26 reaches `READY_FOR_REVIEWER_MERGE`.
> **PROJECT_STATUS != COMPLETE.**

## Why this milestone exists

M2, M3 and M4 each produced a correct, tested, honestly-bounded provider. What
does **not** exist yet is anything that treats them as one system.

| Present (M2/M3/M4) | Absent |
|---|---|
| three correct providers | one place that validates an asset from any of them |
| three receipt shapes | one receipt/asset validator |
| per-provider quota reads | quota-aware ordering across modalities |
| `AudioPolicy` on video | anything that actually *applies* it |
| `AssetPlanner` kinds | no concrete consumer behind them |
| `AssetKind` + registry | no Asset Quality Gate converging all of them |
| one video clip produced | no `final.mp4` assembled from them |

The North Star is `real final.mp4`. Nothing in M2–M4 composes one. M4.5 is the
milestone that makes the parts usable as a pipeline rather than as three demos.

## Scope

### 1. Unified receipt and asset validation

One `validate_media_asset(asset, receipt)` covering speech, image and video.
Today each modality validates its own; a shared validator is what lets a single
quality gate trust any of them. It must assert the **shared** invariants only:

- receipt exists, is complete, and its declared schema matches its producer
- `output_sha256` matches the bytes on disk
- credential class recorded, no credential value anywhere
- no raw provider task id
- `billing_mode=subscription`, `payg_allowed=false`
- `generated` / `evidence_capable` agree with `AssetKind`
- `production_ready` is false unless a human review receipt says otherwise

Per-modality facts (codec, luma stddev, frame-diff distribution) stay in their own
receipts. A shared validator must not grow modality-specific branches, or it
becomes the monolith the provider split was designed to avoid.

### 2. Quota-aware scheduling

All three modalities draw on the **same weekly window**:

| Modality | 5-hour window | Weekly window |
|---|---|---|
| speech | required | required |
| image | required | required |
| video | not applicable | required |

So one video generation can starve the following week's speech. Add an ordering
rule with an explicit, recorded policy: cheap and mandatory work first, then
support visuals, and never let a video task be scheduled when weekly quota is
below a declared floor. The floor is a **policy value**, not a derived formula —
the provider only exposes percentages, and no price is derived from them.

### 3. Provider capability registry

`MediaProviderRegistry` — three members, now that three exist. It was correctly
deferred at two members because a registry was then indirection without benefit.
Responsibilities:

- resolve a provider by modality, never by vendor name
- expose `capabilities()` uniformly so a planner can ask "can you do Ref2VA?"
- hold no billing state; each provider still owns its own `BillingGuard`
- refuse an unimplemented capability with `CapabilityNotSupported`, never a
  silent fallback

### 4. `AssetPlanner` → concrete asset consumer

This is the largest single gap. The planner resolves a beat to a kind; **nothing
currently consumes the result.** Wire the decision to execution:

| Beat resolves to | Action |
|---|---|
| `REAL` / `SCREENSHOT` / `SCREEN_RECORDING` | capture or locate the real file |
| `DIAGRAM` | render deterministically |
| `MINIMAX_IMAGE` | image provider |
| `MINIMAX_H3_VIDEO` | video provider, with `quota_budget` + `test_objective` |

Two rules must survive into the consumer: a **claim-bearing** beat may resolve
only to evidence-capable kinds, and when only support-only kinds are available the
planner refuses and says real or captured material is required. It must never
degrade a claim into a generated visual.

### 5. Apply `AudioPolicy` downstream

`KEEP` / `MUTE` / `REPLACE` is recorded on every video asset and applied nowhere.
Composition must honour it, and the default `REPLACE` must actually strip the H3
track and lay in deterministic narration. Silent mixing of H3 audio and narration
is the failure this exists to prevent.

### 6. Asset Quality Gate convergence

One gate, three modalities, converging on the M3 evidence-integrity rules plus
video technical QC. A generated shot must never pass as evidence, whichever
modality produced it.

### 7. Final QC inputs

Feed `scripts/qc_video.py` and `scripts/qc_visual.py` from the registry rather
than from hand-assembled paths, so final QC reads the same validated assets the
gate approved.

## Explicitly not in M4.5

- Enhancing Golden A/B/C/D (follows M4.5)
- Founder review of the goldens (follows M4.5)
- Cross-repo `SourceArtifact` E2E (#6, M5-M6)
- Verifying Ref2VA reference-video/audio, FL2VA, L2VA or H3-Max live. Only
  spend quota on those if an acceptance item actually requires it.
- `MediaProvider` → `SpeechProvider` rename. Still deferred.

## North Star position after M4.5

```
Real Business Source → SourceArtifact → Evidence/Claim → Brief → Script
→ ShotPlan → AssetPlanner → [REAL|SCREENSHOT|SCREEN_RECORDING|DIAGRAM|
                             MINIMAX_IMAGE|MINIMAX_H3_VIDEO]
→ Asset QC → Easel Compose → Final QC → Human Review → final.mp4
```

M4.5 completes that chain **except** the `SourceArtifact` front end and Founder
approval. Those are #6 / M5-M6 and a human decision respectively.
