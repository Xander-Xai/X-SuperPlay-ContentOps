# PRE-CODE-GATE.md — 编码前必答的 7 个问题

> 每个项目开始 coding 前必须回答这 7 个问题。
> **第 4 个回答不清楚 → 禁止 coding，先调研。**

---

## 7 Questions

```
1. 谁会用？

2. 他现在怎么解决？

3. 我要改善的唯一核心问题是什么？

4. GitHub / SaaS / API 上是否已有 70% 解决方案？

5. 我真正独有的 20% 是什么？

6. 7 天之内最小可交付物是什么？

7. 什么条件出现时我停止这个项目？
```

---

## 详细说明

### 1. 谁会用？

- **具体到一个人**，不是"所有人"
- 目标用户现在 10 分钟内怎么工作
- 他愿意为这个付钱吗？为什么

### 2. 他现在怎么解决？

- 现有工具链是什么
- 哪些步骤是痛苦的
- 痛点有没有数据（耗时、失败率、错误数）

### 3. 我要改善的唯一核心问题是什么？

- **只能是一个**，不是三个
- 用一句话说清楚

### 4. GitHub / SaaS / API 上是否已有 70% 解决方案？

- 如果有 → ADOPT 或 EXTEND
- 如果没有 → 重新评估问题定义

**这是决定 BUILD 还是 EXTEND 的分水岭。**

### 5. 我真正独有的 20% 是什么？

- 数据：我的领域数据、用户行为
- 业务逻辑：账号定位、选题逻辑、归因规则
- 体验：业务流程的整合
- 闭环：数据回流

如果答不出来 → 没有 BUILD 的理由。

### 6. 7 天之内最小可交付物是什么？

- 必须能跑通
- 不需要 100 分，能看能用
- 这一步必须有外部用户能体验

### 7. 什么条件出现时我停止这个项目？

- 明确 kill criteria
- 例如：14 天没有外部结果 → KILL
- 例如：核心问题已被别的方案解决 → 停止

---

## 使用流程

```
项目 idea 出现
  ↓
填写 Pre-Code Gate 表单
  ↓
第 4 题清楚吗？
  ├── No  →  调研，至少看 3 个候选
  └── Yes → 继续
  ↓
第 7 题有明确答案吗？
  ├── No  → 重新想清楚
  └── Yes → 开工
  ↓
Day 7 自检：真实用了吗？
  ↓
Day 14 自检：有外部结果吗？
  ├── No  → 强制 CUT SCOPE / PIVOT / HOLD / KILL
  └── Yes → 继续
```

## 模板（每个项目开新项目时复制）

```markdown
# Pre-Code Gate: <项目名>

## 1. 谁会用？
<具体的人 + 场景>

## 2. 他现在怎么解决？
<现有方案 + 痛点>

## 3. 核心问题
<一句话>

## 4. 70% 解决方案存在吗？
<候选项目 + 评估结论>

## 5. 我的 20% 独特性
<数据 / 业务逻辑 / 体验 / 闭环>

## 6. 7 天 MVP
<Day 1-7 各自要交付什么>

## 7. 停止条件
<明确的 kill criteria>

## 决策
- [ ] ADOPT
- [ ] EXTEND
- [ ] BUILD
```
