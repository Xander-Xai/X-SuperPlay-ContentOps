# PROJECT-STATES.md — 项目状态制度

> 每个项目只允许四种状态。
> **不允许出现"半死不活"状态。**

---

## 四种状态

```
RUN       真正在产生外部结果
HOLD      暂停，不准开发
LIBRARY   只是资产/代码/参考
KILL      明确停止
```

---

## 详细定义

### RUN

- **条件**：正在产生外部结果（用户/发布/收入/数据）
- **行为**：正常开发与发布
- **每个 RUN 项目都要**：有 Pre-Code Gate 文档 + 有 receipt

### HOLD

- **条件**：暂时不开发，但可能未来重启
- **行为**：
  - **不准开发**
  - 不准"小修小补"
  - 不准"偶尔看看"
  - 只读仓库内文件，其他操作需 Founder 同意

### LIBRARY

- **条件**：资产/代码/参考，不再主动开发
- **行为**：
  - 作为代码存档保留
  - 允许被其他项目引用
  - 不允许独立迭代

### KILL

- **条件**：明确停止，不再重启
- **行为**：
  - 仓库标记为 archived
  - 不允许复活（除非 Founder 明确重启）

---

## WIP Limit = 1

**同一时间只允许一个主要 Shipping Project。**

### 优先级

```
RUN (Shipping)       ← 只有一个
RUN (Maintenance)    ← 必要的 bug fix
HOLD                ← 暂停
LIBRARY             ← 资产
KILL                ← 已停止
```

### 每月审视

每月初必须审视所有项目，强制归入四种状态之一。

---

## 禁止的状态（过去最常出现）

```
🚫 "这个项目以后可能有用，所以偶尔继续优化"
🚫 "先做基础，下个月再上线"
🚫 "做了一半舍不得"
🚫 "反正不急慢慢来"
```

这些就是"半死不活"——最吃时间的状态。

---

## douyin-1024 应用示例

```
douyin-1024
  ↓
现状：Fast Lane + 完整 13 阶段 schema
  ↓
目标：RUN（Shipping）
  ↓
但实际：被其他 5+ 个项目分散注意力
```

**强制行动**：
- 其他项目 → HOLD / KILL
- douyin-1024 → 唯一 RUN（Shipping）
- 14 天内：4 条真实发布

---

## 决策树

```
新项目出现
  ↓
Pre-Code Gate 通过了吗？
  ├── No  →  KILL（不开始）
  └── Yes → 继续
  ↓
有 RUN 仓位吗？（WIP=1）
  ├── No  →  HOLD / LIBRARY / KILL
  └── Yes →  RUN
  ↓
Day 14 复盘
  ├── 有外部结果 → 保持 RUN
  └── 没有外部结果 → 强制 CUT SCOPE / PIVOT / HOLD / KILL
```
