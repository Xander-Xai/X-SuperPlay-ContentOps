## Windows 原生隔离候选

本机 `C:\Windows\System32\processmodel.dll` 存在；只读取 DLL 导出后观察到 `Experimental_CreateProcessInSandbox` 符号存在。没有调用该接口，也没有启动进程；符号存在不证明接口实际可用。微软描述的 [AppContainer](https://learn.microsoft.com/en-us/windows/win32/secauthz/implementing-an-appcontainer) 可通过应用身份、文件 ACL 和能力限制资源访问；其 [Create Process in Sandbox](https://learn.microsoft.com/en-us/windows/win32/secauthz/createprocessinsandbox) 接口标为实验性，要求编译后的沙箱描述，并明确空环境参数会继承宿主环境。仓库现有硬性禁用的 Windows 启动原型，尚无经过验证的专属 ACL、受限子进程策略或独立隔离证据。接口和 DLL 的存在均不构成授权或安全证明，真实 Agent 保持未执行。

已新增 Windows 审查准备链：`scripts/inventory_easel_windows_runtime.py` 为项目内已有运行包生成文件摘要清单；`scripts/plan_easel_windows_sandbox.py` 使用已准备的账号任务和运行包清单生成 SBOX 配置，声明输入及运行包只读、输出目录可写、不授予网络能力。格式依据 [Microsoft MXC 固定源码版本](https://github.com/microsoft/mxc/blob/c47ab4f1db7215ca7305ba32a0996ea243806b76/external/windows-sdk/BaseContainerSpecification.fbs)，需要已有的可选 Python `flatbuffers` 包；没有安装依赖。配置生成代码本次未运行、未验证，不创建 AppContainer、不修改 ACL、不调用 Windows 沙箱接口；子进程限制、输入输出隔离、凭据隔离、工具策略、网络行为、运行包来源和实际执行授权均未建立。
