## A gate hole found on the way

`scripts/dev_check.py` printed "ALL CHECKS PASSED" while
`tests/test_absorbed_workflow_docs.py` had a failing test, because the gate
never ran that suite. Two consequences:

- `scripts/run_tests.py` now discovers every `tests/test_*.py` and runs each in
  its own process; `dev_check.py` calls it. A suite that cannot start is a
  failure, never a skip.
- `--missing-from .github/workflows/ci.yml` refuses CI when a suite exists but
  is never named. Four were in that state: `test_script_quality`,
  `test_repo_policy`, `test_presenter_opening`,
  `test_code_animation_composition`.

Two test defects surfaced and were fixed, not muted: the wiring test asserted
`validators_for("brief") == []` (the contract now wires two brief validators),
and the delivery sibling test indexed `validators_for("delivery")[0]` — the
manifest validator — while its name claimed it exercised the sibling publish
plan. It now runs every delivery validator against a valid manifest and adds a
negative case proving a bad sibling plan is refused.

## Independent review — what it caught

A six-lens review with three refuters per finding raised 48 claims and confirmed
27. The most important one was about this round's own work:

- **The provenance check was documented but never called.** Three documents and
  two skills said the `assets` stage required a ledger row to agree with the
  candidate it cites. `validators_for("assets")` ran only the ledger and
  candidate validators, so `validate_ledger_provenance` had no caller outside
  tests. A package with an unknown-licence, 2.0-score login-walled lead and a
  ledger row calling it `owned` passed `workflow_gate.py check --stage assets`.
  It is now a third assets-stage validator, and a test drives the exact scenario
  through `validators_for("assets")` and expects the disagreement.
- **The shared-store routes broke CI.** `path_base: "shared"` was a hard failure
  when `~/.agents/skills` is absent; a GitHub runner has no such directory, so
  the DNA step would have gone red on every clean checkout. An absent store is
  now a warning that names what was not verified, mirroring the absent-catalog
  rule, and a test pins it.
- **`test_presenter_opening` could never pass on a clean checkout.** Wiring it
  into CI exposed it: the audio and generated shot it hashes are gitignored. It
  now skips only when every reported issue is that missing media, and still
  fails on any real contract violation.
- **The drift guard matched comments.** `--missing-from` was a substring search
  over the whole workflow file, so a `# TODO: wire tests/test_x.py` satisfied it.
  It now parses `run:` scalars and block bodies and ignores comments, and it
  always checks the full discovered set even under `--only`.
- **The runner could abort the run.** An uncaught `TimeoutExpired` killed the
  process and skipped every later suite; stderr was dropped whenever stdout was
  non-empty, hiding a crash behind `[ok]` lines. Both fixed.
- **`sources.py` hardening:** NaN passed the 0-10 range check; `promotable()`
  only blocked the literal `"unknown"`; a non-string `source_candidate_id` was
  silently skipped; a malformed bracketed URL escaped as `ValueError`. Each now
  has a test.
- **The skill still instructed the retired toolchain.** `x-superplay-broll-production`
  carried `$env:SENTINEL_PROJECT_ROOT`, `--step assets_plan`, `material_candidates.py`
  and `broll_execute.py`. Every command now names a script that ships here, and the
  upstream `assets_plan`/capture/canary/placement-QC steps are declared not
  implemented instead of documented as runnable.
- **Numbers corrected:** 30 skill trees archived (not 28); `b-roll-finder` is
  declared on `x-superplay-1024` only; `scripts/test_basic.py` is now part of the
  discovered suite set, so the docs that call it one are true.

### Second pass: the fixes were checked too

Re-running the same 24 findings against the fixed tree left 5 still reproducible,
which is why the first pass was not the last:

- **The DNA test still went red in CI.** The shared-store warning I added was not
  in the test's expected-warning set, so `test_account_dna.py` failed on any
  checkout without `~/.agents/skills`. Both host-local warnings are now expected
  by name, and the test was reproduced with `AGENT_SHARED_SKILLS` pointing at a
  missing directory before and after.
- **The drift guard parsed YAML by hand and got it wrong.** A `run: |` block never
  ended on dedent, so a later step's `name:` line was collected as executed
  shell; matching was also a bare substring, so an `echo "tests/x.py is not wired"`
  satisfied it. The parser is indentation-aware, the match now requires a
  `python ... <suite>` invocation with token boundaries, and `tests/test_run_tests.py`
  pins all of it — that suite is itself now wired into CI.
- **Six `sources.py` refusal branches were unpinned** (document not an object,
  candidate not an object, empty id, missing `source_url`, missing `capture_date`,
  non-object score), along with the malformed-input paths in
  `promotable`/`validate_ledger_provenance`.
  Each now has a test; the suite went from 22 to 49 cases.
- **The bookroll skill still named `$env:SENTINEL_PROJECT_ROOT` as its working
  root and `assets_plan` as an approving gate.** Both removed; the skill is now
  rooted at this repository and states that plan review is a conversation, not a
  stage.

Two passes were needed to get an honest green. The lesson recorded here is
specific: a check that is written, documented and tested for *membership* is not
a check that runs — and a guard that decides whether tests run needs its own
tests.
