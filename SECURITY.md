## Reporting a Vulnerability

**Do NOT open a public Issue for security vulnerabilities.**

For security vulnerabilities, contact: (owner-only repository — use GitHub Private Vulnerability Reporting if available, or contact the repository owner directly)

Or email: (owner email — to be added by founder)

## What to Report

Report immediately:
- API keys, tokens, or credentials committed to the repository
- Private repository content exposed in public files
- Cookie or session leakage
- Arbitrary command execution via unvalidated input
- Path traversal vulnerabilities
- Provider secret exposure

## What NOT to Report

- "The code could be more efficient" — open a regular issue
- Feature requests — open a regular issue
- Questions about the project — open a discussion

## When Reporting

Include:
1. Description of the vulnerability
2. Steps to reproduce
3. Potential impact
4. Any suggested fixes (optional)

## Disclosure

We follow a responsible disclosure model. Please give us reasonable time to fix vulnerabilities before public disclosure.
